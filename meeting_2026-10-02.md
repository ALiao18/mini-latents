# mini-latents: two-week update (Sep 18 – Oct 2)

PCA / pPCA / FA from scratch: one shared EM loop, one pluggable noise model (isotropic for pPCA, diagonal for FA).
Goal: correct, readable, and fast enough to port into `latents`.

## Summary

- **Faster.** At N=1000, d=1600, k=5 one EM iteration went from **3.1 s to about 3.5 ms (~900×)**. The log-likelihood alone went from **2.87 s to 1.8 ms (~1,560×)**. Its peak memory fell from **117 MB to 0.17 MB**.
- **Same answers.** Every version passes an independent dense reference check before it is timed. The converged ll/N matches the baseline to within 7e-4 across 161 comparisons; the small gaps come from stopping-rule changes, not from the speedups.
- **Convergence now follows fastfa / latents.** The stopping rule is the relative rule, and the defaults match Byron's (`tol = 1e-8`). pPCA uses its closed-form ML solution by default.
- **Most of Evren's feedback is addressed.** The status of each item is in the table below. What's left is mainly the loop documentation, a test rewrite, naming, and docstrings.

Numbers are from `bench_results/report` (`quick` preset, 1 BLAS thread, Apple Silicon). A fresh re-run of every commit with a sharper per-iteration timer is in progress, and the full-size preset follows it.

## What changed, by theme

### 1. Speed and memory

| Commit | Change | Why it is faster | Measured (largest size in each sweep) |
|---|---|---|---|
| `67242ab` | Diagonal noise passed as a (d,) vector | Ψ⁻¹W is a row scaling, not an O(d³) inverse of a dense Ψ | E-step **728×** (d=1600) |
| `f6b6976` | FA noise update rewritten | No (N,k,k) contraction per feature | FA noise step **139×** (d=1600) |
| `2b0028c` → `f321318` | E-step returns Σₙ E[zzᵀ] (k,k), not an (N,k,k) stack | Posterior covariance M is shared by all samples: Σ E[zzᵀ] = N·M + EzᵀEz | E-step memory **97.8 MB → 0.15 MB** |
| `fbd0a5a` | Cholesky solves and log-determinant | Replaces eigendecomposition plus explicit inverses | log-likelihood **93×**, fit per iteration **89×** |
| `15742d7` | **Woodbury + determinant lemma** in the log-likelihood | Never forms the (d,d) C; works with the (k,k) M⁻¹ = I + WᵀΨ⁻¹W | log-likelihood **16×** more; scaling in d **slope 1.87 → 0.97**; memory **90 MB → 0.17 MB** |
| `3493ff7` | Σₙ xₙ² computed once per fit | The data does not change during EM; an O(Nd) pass with an (N,d) temporary becomes O(d) | re-run in progress |
| *(next commit)* | Xᵀ⟨Z⟩ shared by both M-steps | The noise update reused nothing from the W update | identical fits; timing pending |

Cost of one log-likelihood evaluation:

```
before (dense):  C = W Wᵀ + Ψ          (d,d)
                 chol(C), solve all N  O(N·d² + d³)
after (lemmas):  M⁻¹ = I + Wᵀ Ψ⁻¹ W    (k,k)
                 log|C| = Σ log ψⱼ + log|M⁻¹|
                 Σₙ xₙᵀ C⁻¹ xₙ = Σⱼ ψⱼ⁻¹ Σₙ xₙⱼ²  −  tr(M BᵀB),   B = X Ψ⁻¹ W
                                       O(N·d·k + d·k² + k³)
```

### 2. Correctness and conventions

- **Variance convention** (`f90dcbb`, `0a2d813`): the ML (1/N) convention is used everywhere. The notebook's explained-variance figure was off (44.729% vs ~44.79%).
- **Decrease check runs before the convergence check** (`e2ab607`). Before, a small *decrease* in log-likelihood could be read as convergence.
- **pPCA starts at its closed-form ML solution** (`af5e4c1`, `0d07045`): W = U(Λ − σ²I)^½, σ² = mean of the discarded eigenvalues. EM now has nothing left to do. pPCA defaults to `method="closed_form"`, and EM is still available.
- **No silent clipping**: a singular covariance raises `LinAlgError` instead of being patched with an eps.

### 3. Convergence (fastfa / latents rule)

- `c6f6708` (Sep 29) introduced fastfa's relative criterion and the `FitFlags` result object, modelled on `latents`.
- Tonight the rule became exactly the `latents` GFA form:
  `(ll − ll_base) < (1 + tol)·(ll_old − ll_base)`, which is the same as **latest gain < tol × total gain since the baseline**. The defaults now match fastfa (`tol = 1e-8`).
- **Found:** under this rule, EM started *at* the pPCA optimum never stops, because every gain is rounding noise and `0 < 0` is false. fastfa and GFA never hit this because they start from a random point. Resolved by making the closed form pPCA's default.
- **Found:** with the old defaults (`max_iter=100`), FA stopped **unconverged** on realistic sizes (d=200 needs ~410 iterations).

### 4. API

- `transform` → `infer_latents` (`261fae7`), matching `latents`. `infer_latents` no longer stores its result on the model, again matching `latents`.

## Questions for Byron and Evren

1. **Where is the log-likelihood computed?**
   - fastfa computes it in the E-step, at no extra cost, but its returned parameters are one M-step past the last value.
   - We compute it after the M-step, so `log_likelihood_` matches the returned parameters, but that duplicates work the next E-step does anyway.
   - Proposal: E-step → ll → convergence check → M-step, and stop *before* the M-step. That gets both properties. It also records the starting point's ll.
2. **Work from the covariance S = XᵀX/N, like fastfa?** Each iteration would cost O(d²k) instead of O(N·d·k), independent of N. It wins when N > d, the usual case for neural data. Choose per fit?
3. **What do we call `inverse_transform`?** It computes E[y | x] = C x + d. `latents` has no named function for this; `predictive_performance` writes it inline, and `sample_observations` always adds noise. Options: a free function `observation_mean(latents, obs_params)` next to `sample_observations`, or a method `obs_mean(X)`.
4. **The fastfa noise identity.** At the newly updated W the quadratic term equals half the cross term, so ψ = (Σₙ xₙ² − rowsum(W ⊙ Xᵀ⟨Z⟩)) / N, which is fastfa's `Ph = diag(cX) − sum(cX_beta .* L, 2)`. Adopt it?
5. **Variance floor** (fastfa `minVarFrac = 0.01`, for Heywood cases): adopt it as is?
